## 1. 等级含义

🟢 较易　🟡 中等　🔴 困难　⚫ 极难　⚪ 数据不足

"难度"指在这个方面想拿到录用需要克服的阻力。每个等级都要配一句理由，让用户知道卡在哪里。

## 2. 方向本身 ①–④：脚本自动给出

`iclr_momentum.py` 会按下表算好等级，报告里直接沿用并解释，不要凭感觉改。

| 维度 | 看什么 | 🟢 | 🟡 | 🔴 | ⚫ |
|---|---|---|---|---|---|
| ① 拥挤度 | 最新一年份额 | < 3% | 3%–10% | > 10% | — |
| ② 势头 | 最新一年份额年变化 | 进入 hot 组（28 个内置方向里前 25%） | 其他 | ≤ −0.5 个百分点 | 论文数真的在减少 |
| ③ 录用红利 | 相对录用率差的 95% 区间 | 整体 > 0 | 跨零 | 整体 < 0 | 整体 < 0 且点估计 ≤ −10 |
| ④ 增长去向 | 近 3 年新增论文里被录用的占比 | ≥ 大会整体录用率（论文数不涨时：录用数没减） | 10% 到大会录用率之间（论文数不涨时：录用率没降） | < 10%（论文数不涨时：录用数和录用率都在降） | 论文在涨，录用数反而减少 |

解读要点：
- ② 是 🟢 只代表"少亏一点"（文章回测：hot 组之后三年的相对录用率差平均也是负的），不是保送。
- ① 份额低不等于容易：冷门未必人少，要结合 🐢 跑输大盘一起看。
- 最新一年样本 < 30 篇时，③④ 只作参考；< 10 篇时 ③ 记 ⚪。
- 具体 idea 太细、样本太少时，同时跑它的上一级方向（比如"金融时间序列预测"同时看"时间序列预测"），用上一级方向给市场背景，用细分方向看竞争密度。
- 跑了几个层级时，报告里的 ①–④ 用最贴近用户 idea、且最新一年 ≥ 30 篇的那一层；其他层级写进层级对比表。
- **选择效应**：录用红利可能部分来自"谁在投"。如果细分方向主要是强组、大厂在做（代表作都是大规模实验），高录用率很大程度是他们的实力，而不是方向本身送分。算力少的学生看到大红利时要打折，并在报告里点明。

## 3. 方向本身 ⑤：审稿门槛（搜索 + 经验）

脚本算不了这一项。做 3–5 次有针对性的搜索就够，不要无限搜：
1. 这个方向最近 1–2 届顶会的代表性录用论文：实验规模、baseline 数量、用了哪些 benchmark。
2. OpenReview 上同方向被拒论文的审稿意见，有没有反复出现 "incremental""limited novelty""missing baselines""needs larger scale"。OpenReview 常要求人机验证，程序和搜索都未必拿得到审稿原文：可以试试网页搜索（site:openreview.net + 方向关键词 + incremental），或者看知乎、小红书、X 上对这个方向审稿的公开讨论；都拿不到就跳过这一条，在报告里写明"未取得审稿意见"。
3. benchmark 是否已经刷满（SOTA 之间只差零点几个点、大家都在卷同一个榜）。
4. 代表作是否大多来自有大规模算力或私有数据的机构。

| 等级 | 典型情况 |
|---|---|
| 🟢 | 小规模实验就能说明问题；有提出新问题或新 benchmark 的空间；审稿人认可小而精的分析型工作 |
| 🟡 | 需要标准 baseline + 2–3 个公开 benchmark；中等算力（单机多卡跑几天）能完成 |
| 🔴 | 需要在饱和 benchmark 上刷 SOTA，或需要大规模训练 / 大量 API 调用；审稿意见常见 "incremental" |
| ⚫ | 实质上只有大厂能做：预训练级算力、私有数据、闭源模型内部访问 |

报告里给出 1–2 条依据并附来源链接，比如"近两届录用论文普遍在 7B 以上模型上做实验"。

## 4. 对你来说 ⑥–⑨

先读个人档案；缺的项用默认值，并在报告里标"（假设）"。

### ⑥ 算力和数据

| 等级 | 情况 |
|---|---|
| 🟢 | 需求 ≤ 现有资源 |
| 🟡 | 用一些办法就够：更小的模型、LoRA/QLoRA、公开 API、免费或学校算力 |
| 🔴 | 需求是现有资源的 2–10 倍，或需要很难拿到的数据 |
| ⚫ | 需求超过现有资源 10 倍（比如预训练），或数据根本拿不到 |

量级参考：一张 24GB 消费级显卡能做 7B 以内模型的推理和 LoRA 微调；7B 全参微调需要多张 80GB 卡；只有 API 额度时，适合做评测、prompting、agent 流程类工作。需要真机（机器人）、特殊设备或私有数据的方向，把这些条件一起算进来。

### ⑦ 技能匹配

| 🟢 核心技能已具备（写过或复现过类似代码） | 🟡 1–2 个月能补上 | 🔴 需要 3–6 个月 | ⚫ 超过持有期 |
|---|---|---|---|

### ⑧ 持有期

先估计"从零到能投稿"要多久：第一次写论文的学生通常 6–9 个月（复现 1–2 个月 + 探索 2–4 个月 + 实验和写作 2–3 个月），有经验的人 3–6 个月。定级时用区间中点（第一次写约 7.5 个月，有经验约 4.5 个月），并在报告里写出算式。

| 🟢 持有期 ≥ 预计时间 × 1.5 | 🟡 持有期 ≈ 预计时间 | 🔴 持有期 < 预计时间 | ⚫ 持有期 < 预计时间 × 0.5 |
|---|---|---|---|

持有期要分两层看：**近端里程碑**（资格考、第一篇论文、复试）决定第一篇论文的切口；**总时长**（整个读博或读研）决定方向布局。博士没说近端里程碑时，第一篇论文按 12–18 个月估计，并标"（假设）"。

再结合处境标签（文章的持有期论证）：
- 持有期 < 6 个月：只推荐 🌱，或 🔥 里一个小而确定的切口；对 🐢 🥶 📉 提示"持有期不够等它回暖"。
- 持有期 6–18 个月：以 momentum 为主；🐢 只有在导师有积累时才推荐。
- 持有期 > 3 年：可以考虑 value（在 🐢 甚至 🥶 里逆向布局），但要讲清楚风险。

### ⑨ 导师或合作者

| 等级 | 情况 |
|---|---|
| 🟢 | 导师或合作者就在这个方向，发过相关论文 |
| 🟡 | 导师在相邻方向，或有师兄师姐能带 |
| 🔴 | 没人带，但方向成熟、资料多 |
| ⚫ | 没人带 + 第一篇论文 + 方向很新、资料少 |

## 5. 总评怎么定（不给总分）

1. **方向本身的难度** = ③ ④ ⑤ 里最严重的那一项；如果 ① 是 🔴 而结果是 🟢，上调为 🟡（太拥挤）。
2. **对你来说的难度** = "方向本身的难度"和 ⑥ ⑦ ⑧ ⑨ 里最严重的那一项，取更严重的。
   例外：⑦ 和 ⑨ 都是 🟢（已经具备核心技能、导师就在这个方向）时，"方向本身的难度"降一级再参与比较（⚫→🔴、🔴→🟡）。因为 ③④ 反映的是平均投稿者，圈内人通常能做得比平均好。
3. ② 不参与取最严重，只作修正说明："进入 hot 组，历史上少亏一点"，或"势头在退，窗口在关"。⚪（数据不足）也不参与，但要在可信度里说明，并尽量用上一级方向补上。
4. 一句话总评：「这个方向目前是【标签】：【一句白话解释】。方向本身【等级】，以你的条件【等级】，最大的坎是【最严重的那一项】。」

为什么取最严重而不是平均：投稿是短板决定的。算力不够，或者审稿门槛过不去，其他方面再好也没用；平均分会把致命问题藏起来。

**缩小切口或换时间点后**：最严重的一项来自 ⑤ 或 ⑥（审稿门槛、算力）时，写出"换个切口能到什么等级"，比如换更小的模型、限定场景、只做评测或分析；来自 ⑧（持有期）时，写出"换一个投稿时间点或档位能到什么等级"。数据全是 🟢、却被某一项拖成 🔴 的方向，这一句往往是对用户最有用的结论。

## 6. 推荐投稿档位

CCF 等级和会议截稿日期会变：写报告时联网核对最新的 CCF 推荐目录和截稿日期，不要凭记忆写。已知的最近一次调整：CCF 推荐目录第七版（2026 年 3 月）首次收录 ICLR 并直接列为 A 类，IJCAI 从 A 类降为 B 类。CCF 官网的分类页面可能还是旧版，核对时以第七版目录文件为准。

- **T1 顶会主会**：NeurIPS / ICML / ICLR（机器学习），CVPR / ICCV / ECCV（视觉），ACM MM（多媒体、视频），ACL / EMNLP / NAACL（NLP），KDD / WWW / SIGIR（数据挖掘与检索），AAAI（综合）
- **T2 次一档会议和期刊**：如 IJCAI（CCF 2026 起为 B 类）、AISTATS、UAI、COLING、BMVC、WACV、CIKM、WSDM、ICDM、ECML-PKDD、ICASSP；期刊如 TMLR（滚动投稿，看重论证是否扎实而不是新颖性，适合第一篇）、Neural Networks、Pattern Recognition
- **T3 门槛更低、周期更短**：顶会 workshop、ACL/EMNLP Findings、短文，适合持有期短或第一次投稿
- **领域会议**：机器人方向的 CoRL、RSS、ICRA、IROS、RA-L（这几个在 CCF 目录里的等级差别很大，有的没被收录，务必核对）；金融方向的 ACM ICAIF、KDD 应用数据科学（ADS）track、FinNLP 等 workshop；医疗、科学等方向同理，先搜再推荐

| 对你来说的难度 | 推荐 |
|---|---|
| 🟢 | 冲 T1 主会，T2 备选 |
| 🟡 | 可以冲 T1，同时准备 T2/T3 作为 B 计划；也可以先投 workshop 拿反馈 |
| 🔴 | 以 T2/T3 为主要目标，或者先缩小问题、换个切口再冲 T1 |
| ⚫ | 不建议作为当前的第一个方向；给出更小的替代问题或相邻方向 |

同时检查时间线：列出持有期内能赶上的具体会议和截稿日期，并注明"以官网为准"。
- 截稿时间大多是 AoE（UTC−12），要换算成用户所在时区：北京时间 = AoE + 20 小时，AoE 某日 23:59 就是北京时间次日 19:59。会不会刚好错过，常常就差这 20 小时。
- 国内的评价体系（保研、毕业要求、考核）通常以 CCF 目录为准。TMLR、LoG 这类没被 CCF 收录的 venue 可能不算数，推荐时提醒用户先确认学校的规定。上面的 T1/T2 是按领域共识分的，和 CCF 等级不完全一致（有的顶级 NLP、视觉会议在 CCF 里是 B 类），两种说法要分开讲。
- NLP 会议（ACL / EMNLP / NAACL 等）走 ACL Rolling Review（ARR）：先投某个 ARR 周期拿审稿意见，再 commit 到具体会议。2026 年 10 月周期起执行新规：每篇投稿要指定一位合格的审稿服务贡献者才保证送审（一人最多担保 2 篇），所有作者都要有完整的 OpenReview 资料。学生第一次投时，要提前和导师或合作者确认谁来担任。以当期 ARR 官网为准：https://aclrollingreview.org/sustainable-reviewing-2026

## 7. 各处境标签的切入策略

| 标签 | 策略 |
|---|---|
| 🌱 早期红利 | 速度优先：尽快跑通最小可行实验，尽早挂 arXiv；用大家认可的 benchmark 证明有效 |
| 🔥 拥挤无红利 | 必须差异化：新的问题设定、新的评测维度（可靠性、安全、效率、成本）、跨领域应用（金融、医疗等），或者更严谨的分析；避免"又一个 X 方法，刷 0.5 个点" |
| 🌤️ 升温中·红利不明 | 先用 arXiv 近期势头确认；方向小，更要选准问题；适合作为第二方向试水 |
| 📉 红利变折价 | 审稿人已经疲劳：别做同类增量，去做更深一层的问题（机理、理论、失败分析、评测基准） |
| 📉 红利变折价（趋势） | 同上，但证据还不硬：可以做，前提是有清晰的差异化；报告里说明"只是趋势" |
| 📉 录用折价 | 审稿更挑剔：实验和论证要比平均水平更扎实；考虑投更对口的 T2 或领域会议 |
| 🧱 增长落在拒稿 | 先看最近被录用的少数论文有什么共同点（问题、数据、写法）再决定；持有期短就优先避开 |
| 🐢 跑输大盘 | 竞争并没有变小：有导师积累或持有期长才建议；也可以把这个方向的方法迁移到 🌱/🔥 的问题上 |
| 🥶 真萎缩 | 只在有独特资源或新视角时做；或者把它的技术用到新场景 |
| ➖ 平稳 | 由其他维度决定 |

## 8. 可信度怎么写

- **高**：最新一年样本 ≥ 100 篇，命中样例基本对题，数据来自脚本实时计算。
- **中**：样本 30–100 篇，或关键词有少量误伤，或数据来自预计算快照。
- **低**：样本 < 30 篇，或只能用文章快照 + 网页搜索，或自定义方向没能联网计算。

无论哪种都要写上：这些是历史关联，不是因果；ICLR 以外的会议只能参考。

两个容易误读的地方，报告里顺手说明：
- 脚本的录用率按已决论文算（录用 + 拒稿，不含撤稿、desk reject），所以比官方公布的录用率高。
- 扫描表里的 ✱ 检验的是"当年的相对录用率差是否为零"；文章说 GNN "校正后不显著"，检验的是 2023→2026 的下降趋势。两者不矛盾。
